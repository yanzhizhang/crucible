## What we learned

- **runS (PM's order logic, R33 / R33b / runs_fit):**
  - `pos` = holding − base target, exact for 99.9 % of decisions.
  - `cpos = pos + pp` exactly.
  - `asf` is 0.8; `winsdQty` = 3/17 × the market-volume EMA.
  - Orders mostly come from `lthr = 0` decisions near the open, with `executp` ≈ ±asq.
  - Order size is driven by the position gap, not by the prediction (corr with fa 0.13).
- **s1..s4:**
  - Training ranges split the day at 09:40 / 10:00 / 14:30 (ratio 1 : 3 : 21 : 23.7).
  - But PM's live alpha follows **s1 all day** (R30 / R31). We keep s1.
- **Label:** a decimal return. PM's alpha std is 3.4e-4.
- **Seeds (R28, R36):** seeding the engine with yesterday's state changes only the first half hour, and slightly for the worse. It changes nothing after that. No stateful column improved with seed candidates.
- **Paths:**
  - 224's `/tmp/s/stsfile` is a byte-identical mirror of 2.23's `/data/share/s`.
  - On 1112, runS asked for `index-20261112.xr`, which did not exist anywhere, and used the 1109 files.
  - The 1112 sod `.jz` link was made at 11:26, so 224's seed on 1112 was 1110.
- **Bug found and fixed:** the Barra industry dummies are 1/NaN, not 0/1. ic_score's `neu:` / `dmi:` candidates and static_resid's industry table were silently empty. They have been fixed since R37b.
- **Residual (R35b, after R34):**
  - The size / liquidity bias is gone.
  - We over-carry short-term imbalance and microprice, while PM carries more order flow.
  - But R39 shows those columns are still needed: dropping all 37 of them gives 0.32. They need retuning, not removal. That is R40.
