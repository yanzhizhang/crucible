## What p1..p10 mean (checked 20:45, readlink on 2.23, raw: 97 data/reports/share23_pN_1112.txt)
`pN/<D>` is a link to the file from **N trading days before D** (a lag view, not versions or passes). For D = 20261112:
| N | 1min_src | CEDxr4d/daily (_SOD) | index/1min_src | CEDxr4d/index/daily_eod |
|---|---|---|---|---|
| p1 | 20261111 | 20261111 | 20261111 | 20261111 |
| p2 | 20261110 | 20261110 | 20261110 | 20261110 |
| p3 | 20261109 | 20261109 | 20261109 | 20261109 |
| p5 | 20261105 | 20261105 | 20261105 | - (only p1..p3 exist) |
| p10 | 20261029 | 20261029 | 20261029 | - |
The counts skip weekends: p3 from 1112 is 1109 and p10 is 1029.
So a job can read "its last N days" at fixed paths p1..pN/D without a calendar. `h/HS300/sod/p1_intrading_dcp` is the
same idea with N=1: the previous day's intraday state, which is the seed. h/HS300 holds livev1, p1_intrading_dcp, sod.
