## 3. 已定的 144 列

公式在 `research/engine/baseline_r41c.txt`，有 5 列直接用到 `.jz` 状态：
- zzup = zzup.pf / zzup.ps
- zzvx.a = zzvx.trDEmaD / px
- zzxu.a = zzxu.a / zzxu.low
- zzxu.b = (px − zzxu.a) / zzxu.last

其余都是 tick 级基础量（gen.*）加上前缀写法：`cal:`、`dm:`、`dmi:`、`neu:`、`srank:`、`rank:`、`crank:`、`z:`、`|x|*1e4`。

注意：已定只说明这一列"打分时有效、能通过单位检验"，**不等于逐位一致**。审计结果是只有约 28% 到 31% 的增益经过了训练分布的验证。要做到逐位一致，已定的列也需要逐列复核。

## 4. 补的顺序（按增益和可行性）

1. **把 zzeg.c 补进引擎**：4 天通道加 rEma，再定 zzeg 的公式。R111 正在拟合 rEma 的时钟和半衰期。
2. **zzvm.c.re、zzmh.r、zzhj.p/c、zzcb.r、zzxo.r.#** 这些没造的均线和网格补进引擎，然后用"状态 / 现价"一类写法去对 zzvm、zzmh、zzhj、zzcb、zzxo。
3. **两天都对不上的已造状态** zzgh.nb、zzup.ps、zzba.p，重新查规则；其余的在非凸行情补齐后再复测。
4. 没有 `.jz` 状态的开放列（zzel.a/b、zzop.i、zzpe.e、zzzl2.c/g、zzsf.*、zzjx*、zzsa* 等），从 tick 基础量里找积木。有树根分裂点的列先用单位检验（`research/featgen/fingerprint.py`）。
5. 已定的 144 列逐列复核，看是否逐位一致。
